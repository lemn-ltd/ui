## Source contract

`@lemn-ltd/brand-contract` defines the versioned authoring format:

```json
{
  "$schema": "https://schemas.ui.le-mn.com/brand-project/v2.json",
  "schemaVersion": 2,
  "brandId": "example_brand",
  "name": "Example Brand",
  "defaultProfileId": "core",
  "profiles": {
    "core": {
      "name": "Core",
      "defaultMode": "light",
      "typography": {
        "catalogVersion": 1,
        "body": {
          "source": "system",
          "ref": "system.ui",
          "fidelity": "preferred",
          "emergencyFallbackRef": "system.sans",
          "weights": [400, 500, 600],
          "styles": ["normal"]
        },
        "heading": { "source": "inherit", "role": "body" },
        "code": {
          "source": "system",
          "ref": "system.mono",
          "fidelity": "preferred",
          "emergencyFallbackRef": "system.ui",
          "weights": [400, 600],
          "styles": ["normal"]
        },
        "baseSize": 16,
        "displaySize": 52,
        "titleSize": 30,
        "bodyLineHeight": 1.5,
        "headingLineHeight": 1.1,
        "tracking": 0
      },
      "modes": {
        "light": {},
        "dark": {}
      }
    }
  }
}
```

The abbreviated mode bodies above are illustrative. A valid source provides
the schema's complete Profile typography and each mode's color, shape, elevation,
spacing/density, motion, visualization, iconography, accessibility, and
component-appearance sections.

Profiles are intentional expressions such as Core, Pediatrics, Executive, or
Campaign. A Profile may inherit from one acyclic parent and contain multiple
modes. Runtime selection changes a complete Profile/mode scope atomically; it
does not patch individual root variables.

## Compiler output

`compileBrandProject` validates and resolves source data, applies safe derived
values, and emits an immutable artifact with:

- schema/compiler compatibility;
- source and compiled SHA-256 hashes;
- inheritance-free Profiles and modes;
- critical scoped CSS using stable `--lemn-*` roles;
- selected immutable WOFF2 resources, preload policy, and `@font-face` rules;
- DOM scope attributes and color scheme;
- chart-provider adapters behind artifact fields;
- managed asset references; and
- errors/warnings for contrast, focus, visualization, assets, and policy.

Every project compiles to the same semantic vocabulary. Project or Profile IDs
belong in the scope attributes and artifact identity, never in CSS variable
names.

## Authoring with Brand Studio

Install Studio with an exact compatible release:

```bash
pnpm add @lemn-ltd/brand-studio@0.2.0
```

```tsx
import { BrandStudio } from "@lemn-ltd/brand-studio";
import "@lemn-ltd/brand-studio/styles.css";

<BrandStudio
  value={draft}
  onChange={setDraft}
  onIntent={handleAuthorizedIntent}
/>
```

Seeds, SSR tooling, and CLIs import presets from the Node-safe subpath, which
does not evaluate React or CSS:

```ts
import { createBrandFromPreset } from "@lemn-ltd/brand-studio/presets";
```

The wizard exposes identity, starting presets, managed assets, Profiles/modes,
semantic colors, governed Profile typography, shape/elevation, density/motion, visualization,
accessibility, constrained component appearance, and source/resolved/compiled
review.

Typography uses a curated catalog rather than arbitrary family strings. System
choices request 0 KB. Managed choices are self-hosted at
`fonts.ui.le-mn.com`, expose `preferred` or `required` fidelity plus a system
emergency fallback, and only compile the selected family/styles. `preferred`
uses optional loading; `required` isolates its internal family per Profile,
preloads it during SSR, and uses the browser font block period so the first
text paint does not use the fallback. A permanent download failure can still
activate the declared emergency fallback rather than hiding content forever.

Studio is controlled and persistence-free. The host must authenticate and
authorize the project, validate expected revision/idempotency, persist drafts,
plan/apply publication, separate production approval, record audit, and deliver
runtime artifacts.

## Contrast policy

Publication validates declared text/surface, accent/on-accent, state,
border/focus, and chart-label relationships against WCAG 2.2 AA policy.
Automatic correction may adjust derived on-colors, hover/pressed tones,
borders, and chart labels within policy; it never silently changes the authored
primary brand color. Blocking diagnostics prevent publication.

## Evolution

Additive fields may remain in schema major 2 only when defaults preserve
behavior. Incompatible meaning/removal requires a new schema major and explicit
migration. Future settings belong under validated standard fields or namespaced
`extensions`; arbitrary CSS and behavior flags are not branding.
