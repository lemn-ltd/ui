## Superficies

- Cuatro paquetes publicos se publican en GitHub Packages en orden de dependencia:
  Brand Contract, UI, Brand Runtime y Brand Studio.
- `ui.le-mn.com` sirve Docs.
- `showcase.ui.le-mn.com` sirve Showcase publico read-only.
- `admin.showcase.ui.le-mn.com` sirve Admin separado con Cloudflare Access.

La identidad del paquete, commit, provenance/notices/SBOM y deploy deben referir
al mismo release aprobado.

## Gates

```bash
pnpm validate
pnpm check
pnpm test
pnpm build
pnpm audit --prod
pnpm changeset status
```

Ademas se prueba registry exacto, una implementacion activa por capacidad,
installs limpios, conformance aplicable, dry-runs de Cloudflare, credenciales
least-privilege, rutas publicas/protegidas, identidad del build y recovery. No
se reutiliza evidencia de otro commit.

El GitHub Environment protegido aporta exactamente
`PRODUCTION_CLOUDFLARE_API_TOKEN` y `PRODUCTION_STATUS_TOKEN`. El API token de
Cloudflare pertenece a Account `Lemn DEV` y tiene solo `Workers Scripts: Edit`
(la API lo reporta como `Workers Scripts Write`); sobre Zone `le-mn.com` tiene
`Zone: Read` mas `Workers Routes: Edit` (la API lo reporta como `Zone Workers
Routes Write`). No se otorga KV, R2, account settings, permisos de usuario ni
zonas mas amplias. El guard rechaza Global API Key, modo key/email, tokens
ausentes/expirados/deshabilitados y cuentas incorrectas.

## Secuencia

1. Valida y empaqueta la revision exacta.
2. Publica Brand Contract, UI, Brand Runtime y Brand Studio; una version
   existente debe tener integridad inmutable identica.
3. Instala paquetes exactos en consumidores externos limpios.
4. Despliega Docs y Showcase.
5. Despliega Admin y verifica denial sin auth mas comportamiento autenticado.
6. Hace smoke de catalogos, System brandings/modes, schema v1, blocks, registry
   e identidad.
7. Registra el receipt solo cuando pasan todos los gates.

Secrets, tokens, account keys, headers y credenciales nunca entran en archivos,
args, artifacts, logs o docs. Un fallo de identidad/integridad/concurrencia/smoke
detiene el rollout.

Para Showcase se inspecciona el baseline con `wrangler deployments list
--json`, se sube una candidata inactiva, se prueban rutas publicas y protegidas
con su `PRODUCTION_STATUS_TOKEN`, y solo entonces se activa esa version exacta.
La credencial de status del baseline se conserva en el proceso de rollout hasta
el smoke estable. Un fallo posterior ejecuta `wrangler rollback
<captured-version-id> --yes` y vuelve a verificar el baseline. Las credenciales
viven solo en el Environment; no queda ninguna credencial retirada key/email a
nivel de repositorio.

La evidencia final incluye nombres/versiones/integridad de paquetes, commit y
deploy IDs, dominios/Access, smokes, y respuesta SSR sin JavaScript con CSS de
scope y `compiledHash` antes de hydration.
