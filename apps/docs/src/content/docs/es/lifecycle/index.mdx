`@lemn-ltd/ui` usa SemVer para el paquete publicado.

- `PATCH`: bug fixes, fixes internos, correcciones de docs y polish visual no breaking.
- `MINOR`: nuevos componentes, nuevos exports, variantes, props aditivas y comportamiento no breaking.
- `MAJOR`: exports removidos, props renombradas, cambio de semantica o cambios que requieren migracion.

## Ownership de release

El autor del feature o el agente agrega un changeset con la intencion de
release. La automatizacion convierte los changesets mergeados en un commit de
metadata de release que actualiza `packages/ui/package.json` y
`packages/ui/CHANGELOG.md`.

El workflow de produccion completa el preflight no mutante de la Global API Key
de Cloudflare antes de que Changesets pueda versionar, pushear o publicar. Luego
captura el SHA del commit de release y despliega ese SHA y version exactos.
El mismo guard exclusivo de `main` protege los entrypoints CLI directos, por lo
que las credenciales en un feature checkout no autorizan versionado,
publicacion ni deploy.

CI publica el paquete solo cuando una lista autenticada de GitHub Packages omite
la version generada exacta y el package scope coincide con el owner del
repositorio. Un estado de registry no verificable falla cerrado antes de la
publicacion.

## Comandos

```bash
pnpm changeset
pnpm version:packages
pnpm release
```

Ejecuta comandos mutantes de produccion solo desde `main`. `pnpm publish:ui`
builda el paquete y `prepublishOnly` exige todos los exports y completa el smoke
estricto del tarball instalado, TypeScript y Vite antes de que npm pueda
publicar metadata inmutable.

Usa prereleases solo para rollouts staged explicitos.
