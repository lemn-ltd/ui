El release publico incluye `@lemn-ltd/brand-contract`, `@lemn-ltd/ui` y
`@lemn-ltd/brand-studio`. Los consumidores pinnean versiones exactas compatibles.

- **PATCH**: fixes compatibles sin cambiar el contrato publico.
- **MINOR**: componentes/blocks/props/campos aditivos con defaults compatibles.
- **MAJOR**: exports removidos/renombrados, semantica incompatible, nuevo major
  de schema/compiler o reemplazo que requiere migracion.

## Update de proveedor

1. Detecta upstream sin cambiar produccion.
2. Propone origen/integridad/licencia exactos en el registry.
3. Revisa delta API, comportamiento, a11y, interaction, visual, SSR y bundle de
   las capacidades seleccionadas.
4. Actualiza adaptador o patch explicito sin reescribir comportamiento.
5. Ejecuta conformance, notices/SBOM, migration y changeset.
6. Publica por el workflow normal.

No se permiten catalogos completos, versiones flotantes, branches ni patches
silenciosos.

## Orden de publicacion

1. `@lemn-ltd/brand-contract`
2. `@lemn-ltd/ui`
3. `@lemn-ltd/brand-studio`
4. Docs, Showcase y Showcase Admin del mismo release

Despues se prueban installs limpios desde GitHub Packages y consumidores reales
con versiones exactas, nunca links de workspace.

```bash
pnpm changeset:add
pnpm validate
pnpm check
pnpm test
pnpm build
pnpm version:packages
pnpm release
```

El preflight de produccion acepta solo `PRODUCTION_CLOUDFLARE_API_TOKEN`, con
scope Account `Lemn DEV` / `Workers Scripts: Edit` (`Workers Scripts Write` en
la API) y Zone `le-mn.com` / `Zone: Read` mas `Workers Routes: Edit` (`Zone
Workers Routes Write` en la API). Credenciales o modos de autenticacion mas
amplios fallan cerrado.
