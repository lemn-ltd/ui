`@lemn-ltd/brand-contract` define
`https://schemas.ui.le-mn.com/brand-project/v2.json`. Un BrandProject tiene una
identidad, assets gestionados, Profiles y un Profile por defecto. Cada Profile
puede heredar de un solo padre aciclico y contener multiples modes.

El contrato cubre colores semanticos, tipografia gobernada por Profile, shape, elevation,
spacing/density, motion, visualizaciones, iconografia, accesibilidad y
apariencia restringida. Arbitrary CSS y behavior flags no son branding.

## Output compilado

`compileBrandProject` produce un artefacto inmutable con compatibilidad de
schema/compiler, hashes SHA-256, Profiles resueltos, CSS critico con scope,
atributos DOM, adaptadores de charts, assets y diagnosticos. Todos los proyectos
usan el mismo vocabulario `--lemn-*`; identidad vive en el scope, no en el nombre
de variables.

## Brand Studio

```bash
pnpm add @lemn-ltd/brand-studio@0.2.0
```

```tsx
import { BrandStudio } from "@lemn-ltd/brand-studio";
import "@lemn-ltd/brand-studio/styles.css";

<BrandStudio value={draft} onChange={setDraft} onIntent={authorizedIntent} />
```

Seeds, herramientas SSR y CLIs importan presets desde el subpath seguro para
Node, sin evaluar React ni CSS:

```ts
import { createBrandFromPreset } from "@lemn-ltd/brand-studio/presets";
```

El wizard cubre identity, presets, assets, Profiles/modes, colors, typography,
shape/elevation, density/motion, visualizations, accessibility, apariencia y
review JSON/compiled.

Typography usa un catalogo curado en vez de nombres libres. Las opciones de
sistema descargan 0 KB; las administradas se sirven desde
`fonts.ui.le-mn.com`, permiten fidelidad `preferred|required`, conservan un
fallback de emergencia y compilan solo la familia/estilos seleccionados.
`preferred` prioriza carga opcional. `required` aisla el alias interno por
Profile, genera preload SSR y usa el periodo de bloqueo del navegador para que
el primer pintado de texto no use el fallback. Un fallo permanente todavia
activa el fallback declarado en vez de ocultar contenido indefinidamente.

Studio es controlado y sin persistencia. El host autentica/autoriza, guarda
drafts, valida expected revision/idempotency, planifica/aplica publicacion,
separa aprobacion de produccion y registra audit.

Publication verifica WCAG 2.2 AA para relaciones declaradas. Correcciones
automaticas solo modifican roles derivados dentro de politica; nunca cambian
silenciosamente el color primario. Errores bloquean publicacion.
