Lemn UI es un ecosistema provider-first, no una coleccion de widgets reescritos.
LEMN selecciona capacidades open source battle-tested de forma individual,
asigna un proveedor de registro a cada capacidad semantica y expone una API
neutral con una capa minima de branding compilado.

## Que posee este workspace

- `@lemn-ltd/brand-contract`: `BrandingDefinition` v1, compilador determinista,
  diagnosticos, envelope firmado, tokens, fonts y temas Recharts/ECharts.
- `@lemn-ltd/brand-runtime`: resolucion server-only, verificacion, proyeccion de
  un mode, helpers SSR y un fallback branded embedded.
- `@lemn-ltd/ui`: componentes controlados, charts, estilos, blocks y catalogos.
- `@lemn-ltd/brand-studio`: wizard controlado, sin persistencia, con preview de
  componentes reales e intents tipados ejecutados por el host.
- Registry Git-authoritative con origen exacto, licencias, adaptadores,
  conformance y updates revisados.
- Un UI Portal con Catalogo publico y Admin protegido por Access bajo el mismo
  Worker e identidad de release.

## Limites no negociables

- Los consumidores instalan versiones exactas; nunca `latest`.
- No importan un provider upstream para una capacidad del catalogo.
- Los componentes consumen roles `--lemn-*`, nunca JSON fuente ni variables
  especificas de un Workspace.
- El host resuelve y verifica branding antes del primer byte HTML.
- AgentOps posee Workspaces, versiones, persistencia, publicacion, activacion,
  previews, autorizacion y audit.
- Fetching, routing, auth, estado global, i18n, analytics y politica quedan
  fuera de UI.
