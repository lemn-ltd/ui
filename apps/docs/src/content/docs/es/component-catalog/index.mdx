`componentCatalog` es el inventario data-only actual de componentes publicos.
Cada entrada declara slug, area, familia, madurez, titulo e intent. El export,
Showcase y los drift tests son autoridad; las docs no congelan un total.

Core cubre primitives, inputs, forms, visualizations, data display, feedback,
overlays, navigation y layout. Agents cubre conversation, governance,
approvals, automation y runtime/evidence.

`blockCatalog` es independiente. Un block es una composicion con proposito, no
otra implementacion de un primitive. Ve [Blocks](/es/blocks/).

Cada capacidad semantica mapea a exactamente un proveedor activo en el registry
versionado. Origen exacto, integridad, licencia, notices, adaptador, roles de
branding, conformance y estado upstream pertenecen al registry; el consumidor
solo importa el export LEMN.

Agregar una capacidad exige alinear registry/provenance, adaptador, exports,
catalogos, docs, Showcase, conformance, release y licencias. Cada pagina de
componente usa el componente real y como maximo tres ejemplos.
