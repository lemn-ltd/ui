## 1. Configura GitHub Packages

Commitea solo el mapping del scope:

```ini
@lemn-ltd:registry=https://npm.pkg.github.com
```

Mantiene auth en `~/.npmrc`, nunca en el repo:

```ini
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
```

## 2. Instala releases exactos compatibles

Para una aplicacion SSR:

```bash
pnpm add @lemn-ltd/brand-contract@1.0.0 @lemn-ltd/brand-runtime@0.1.1 @lemn-ltd/ui@0.4.0
```

Para un host de authoring autorizado:

```bash
pnpm add @lemn-ltd/brand-studio@2.0.0
```

No uses `latest`, rangos, branches, URLs, `workspace:*`, `link:` ni rutas
relativas cross-repo en un consumidor publicado.

## 3. Importa entrypoints publicos

```tsx
import { Button, Card, componentCatalog } from "@lemn-ltd/ui";
import "@lemn-ltd/ui/styles.css";
```

Carga estilos una vez. No hagas deep import de `src`, `dist`, internals ni de un
provider upstream.

## 4. Aplica branding antes de renderizar

Los componentes nunca parsean JSON fuente. Un server confiable resuelve una
version publicada del Workspace, verifica la proyeccion minima firmada del mode
y su projection hash canonico, e inyecta CSS, preloads, atributos y bootstrap
antes del primer markup. El objeto compilado completo permanece privado en el
storage de publicacion. Usa `@lemn-ltd/brand-runtime`; no recrees verification
en producto. Sigue el [runbook SSR](/es/ssr-branding/).

## 5. Mantiene plataforma fuera de UI

El host posee API clients, fetching, routing, auth, estado global, i18n,
analytics, persistence, Workspace routing, cookies y politica. Pasa valores y
acciones controladas a componentes y blocks.
