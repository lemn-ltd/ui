## Release surfaces

- `@lemn-ltd/brand-contract`, `@lemn-ltd/ui`, and
  `@lemn-ltd/brand-studio` publish to GitHub Packages in dependency order.
- `ui.le-mn.com` serves this Starlight documentation.
- `showcase.ui.le-mn.com` serves the public read-only Showcase.
- `admin.showcase.ui.le-mn.com` serves the separately deployed Showcase Admin
  behind Cloudflare Access.

Package identity, source commit, generated provenance/notices/SBOM, and deployed
build identity must all refer to the same approved release.

## Required gates

Before any mutation:

```bash
pnpm validate
pnpm check
pnpm test
pnpm build
pnpm audit --prod
pnpm changeset status
```

The release workflow must also prove:

- exact provider registry pins and one active implementation per capability;
- compatible package dependency order and clean GitHub Packages installs;
- provider, brand contract, SSR, accessibility, interaction, visual, and bundle
  conformance applicable to the change;
- Cloudflare configuration dry-runs and least-privilege credential preflight;
- public/protected route behavior and deployed build identity;
- rollback or recovery metadata before shifting production traffic.

Do not represent an earlier commit's checks as evidence for the release SHA.

## Authentication and authorization

GitHub Actions supplies its job token for package publication. Cloudflare
credentials are resolved only inside the protected production environment and
must be scoped to the owned account/resources and required actions. Never place
tokens, account keys, auth headers, or secret values in repository files,
command arguments, build artifacts, logs, or documentation.

The protected GitHub Environment supplies exactly
`PRODUCTION_CLOUDFLARE_API_TOKEN` and `PRODUCTION_STATUS_TOKEN`. The Cloudflare
token is an account-owned API token scoped to Account `Lemn DEV` with `Workers
Scripts: Edit` (reported as `Workers Scripts Write` by the API), and Zone
`le-mn.com` with `Zone: Read`. Do not grant Workers Routes, KV, R2, account
settings, user, or wider zone access. The release guard rejects Global API Key,
key/email, missing, expired, disabled, and wrong-account authentication.

Showcase is public/read-only. Showcase Admin requires a cryptographically
verified Cloudflare Access application assertion and uses only narrow server
adapters. Network location or a Service Binding is not business authorization.

## Deployment sequence

1. Validate and pack the exact source revision.
2. Publish Brand Contract, then UI, then Brand Studio; an existing version must
   have identical immutable integrity or the release stops.
3. Install the exact published packages in clean external consumers and run
   their checks/builds.
4. Deploy Docs and public Showcase for that release identity.
5. Deploy protected Showcase Admin and verify unauthenticated denial plus
   authenticated behavior.
6. Smoke public catalog/agent endpoints, branded Profile/mode switching, blocks,
   provider read models, and build identity.
7. Record the release receipt only after every required check passes.

Use staged/traffic-safe Worker versions where the deployment workflow supports
them. Any observed concurrent deployment, identity mismatch, integrity
mismatch, or failed smoke stops the rollout rather than overwriting external
state.

For Showcase, inspect the captured baseline with `wrangler deployments list
--json`, upload an inactive candidate, smoke public and protected routes with
the candidate's `PRODUCTION_STATUS_TOKEN`, then activate that exact version.
Keep the baseline status credential available to the rollout process until the
active smoke is stable. A failure after activation runs `wrangler rollback
<captured-version-id> --yes` and re-verifies the baseline. Credentials are
Environment-scoped only; no retired repository key/email credential is kept.

## Post-deploy evidence

Capture without secrets:

- package names, exact versions, and registry integrity;
- Git commit and deployment/version identifiers;
- domain mappings and Access boundary results;
- public and protected smoke status;
- SSR first-response evidence showing critical scoped CSS, scope attributes,
  and matching compiled hash before hydration;
- rollback/fallback verification and any remaining explicit exception.

This runbook applies `PAT-UI-PROVIDER-FIRST-001`,
`PAT-UI-SSR-BRANDING-001`, `PAT-SEC-SECRETS-001`,
`PAT-CLOUDFLARE-WRANGLER-CONFIG-001`, `PAT-OPS-LEAST-PRIVILEGE-001`, and
`PAT-TEST-EVIDENCE-001`.
