Lemn UI is a provider-first UI ecosystem, not a collection of locally rewritten
widgets. LEMN selects individual battle-tested open-source capabilities, gives
each semantic capability exactly one provider of record, and exposes a stable
provider-neutral API with a minimal compiled branding layer.

## What this workspace owns

- `@lemn-ltd/brand-contract`: versioned BrandProject schema, validator,
  deterministic compiler, diagnostics, scoped CSS, provider adapters, and
  integrity hashes.
- `@lemn-ltd/ui`: controlled components, visualizations, semantic styles,
  blocks, and public catalog metadata.
- `@lemn-ltd/brand-studio`: controlled, persistence-free wizard and live
  preview for authoring BrandProject JSON.
- A Git-authoritative provider registry with exact immutable origins, licenses,
  notices, adapters, conformance, and upstream update status.
- Public Docs and Showcase plus a separately protected Showcase Admin surface.

## Non-negotiable boundaries

- Product code imports only exact approved `@lemn-ltd/*` package versions.
- Product code never imports an upstream UI provider for a catalog-owned
  capability.
- Components consume compiled `--lemn-*` semantic roles, never raw BrandProject
  JSON or project-specific variable names.
- Production hosts resolve and verify branding before the first HTML byte.
- Data fetching, routing, authentication, global state, internationalization,
  analytics, persistence, and product policy stay outside the UI packages.
- Provider updates are reviewed registry proposals, never silent upgrades.
